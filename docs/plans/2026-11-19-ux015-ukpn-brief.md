# UX-015 — one independent UK outage origin

High Assurance provider/network task. Fresh canonical base `ffb3f3ccb4`;
isolated `codex/ux015-ukpn-outages` branch. A complete roadmap snapshot after
UX-014 draft #1918 selects UX-015 [C] with no blockers. Bradley approved the design, draft claim and local implementation on November 19.
Publish the reviewed documentation claim before implementation; later code
publication requires separate approval.

## Objective and acceptance

Show official reported UK Power Networks outages with explicit source, coverage,
time and uncertainty. Qualify one origin only. Keep existing US county ODIN
evidence separate; never sum overlapping sources or interpret UK data as FIPS.
Missing reports must not imply no outage, power availability or safe access.

Discovery found a public UKPN Live Faults API and CC BY 4.0 metadata. A bounded
100-record response includes restored, unplanned and ambiguous multiple records;
some lack coordinates. Architect must establish exact accepted types, timestamps,
pagination/completeness, temporal bounds and regional presentation before coding.
Ground the design in retained live response bodies, not an HTTP status alone.

## Constraints, unknowns and risks

Source advertises partial coverage, omitted small faults and aggregated locations.
Do not render coordinates as exact impacted addresses or claim all UK coverage.
Determine observation/update versus creation/restoration times; preserve stale
and unavailable states. A successful fetch with zero usable observations must
not create a healthy corroboration vote. Use enum allowlists, explicit coordinate
and numeric checks, bounded requests/cache/body size, and malformed-body rejection.

Current outage contracts hardcode ODIN and exact US county FIPS. Preserve that
path. Choose the smallest separate UK projection that actually reaches an
appropriate existing UI; do not stop at an unused adapter or broaden hotel/fuel
truth boundaries. Explain cache/expiry/withdrawal behavior and rollback.

## Owners, validation and non-goals

Repository analyst owns discovery and live shapes; architect owns approved
data/control-flow design. Provider specialist owns acquisition/normalization,
UI specialist any bounded surfacing, test engineer behavior and mutation proofs,
parent roadmap/evidence and integration. Independent Sol and actual Sonnet
reviews precede publication. Run targeted provider/UI/security regressions,
type checks, secret scanning and the named agentic validation gate.

No new dependencies, credentials, account signup, production data writes,
notification policy, global outage rollup or implied independence from unknown
origins. No provider implementation until approval. Merging, auto-merge, releases,
deployment and installation remain paused; no app launch or installed profile.
