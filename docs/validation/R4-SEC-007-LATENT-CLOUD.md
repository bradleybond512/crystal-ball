# R4-SEC-007 + R4-LOW-006 validation: latent cloud routes (Q19)

Plan: `docs/plans/2026-10-04-q19-latent-cloud-routes.md`, approved by Bradley
on October 4, 2026 with every recommended option:

- A: fix now;
- B: sanitize and fence the context;
- C: 500 calls a day per route;
- D: fix the caches and require the app key.

Stacked on `claude/r4-sec-008-csp-owned-domains` (#1769).

No cloud API is deployed, so nothing changes for a live user. The desktop
sidecar runs the same gateway, so the country-code and context hardening
applies to local briefs too.

## What changed

- **`api/_api-key.js`:** `validateApiKey(req, { costBearing })`.
  - On a cost-bearing route, browser fetch-metadata headers (forgeable outside
    a browser) never stand in for `X-CrystalBall-Key`, whatever the method.
  - `isSidecarRuntime()` is exported, and sidecar mode still passes.
- **`server/_shared/llm-guard.ts`** (new, no imports):
  - `COST_BEARING_RPCS`: the brief, `classify-event` and `summarize-article`.
  - The daily cap: `CRYSTALBALL_LLM_DAILY_CAP`, default 500. A value of 0
    blocks every call. A value that can't be parsed falls back to 500, never
    to unlimited.
  - The Upstash `INCR` + `EXPIRE NX` counter, keyed per UTC day.
  - `sanitizeLlmContext`: strips C0/C1 controls, zero-width, bidi and BOM
    characters, keeps newlines and tabs, and caps at 2,200 characters.
  - `fenceUntrustedContext`: wraps the text in an `<untrusted_context>` block,
    adds a do-not-follow instruction, and neutralises any fence tags inside
    the text.
- **`server/_shared/rate-limit.ts`:** `checkRateLimit(..., { failClosed })`
  returns 503 when no limiter is configured. Limiter errors already returned
  503.
- **Gateway (`api/[domain]/v1/[rpc].ts`).** Cost-bearing routes in cloud mode:
  - need a key;
  - fail closed without a limiter;
  - pass the daily cap (429 when exceeded, 503 when the counter store is
    unavailable).

  The brief's cache tier is now `no-store`, so a keyless caller can't read a
  CDN copy of an answer a keyed caller paid for.
- **`get-country-intel-brief.ts`:**
  - An unknown `country_code` returns 400 before any LLM call.
  - The context is sanitized and fenced.
  - The system prompt now says the context is untrusted.
- **`server/_shared/country-codes.ts`:** generated by
  `scripts/generate-country-code-allowlist.mjs` from the app's own map data
  (`public/data/countries.geojson` after `POLITICAL_OVERRIDES`, plus
  `TIER1_COUNTRIES`), 239 codes. It is generated rather than typed by hand,
  and a `--check` drift test keeps it in step with the map.
- **`api/claude-agent.js`:** a missing or failing limiter now returns 503 in
  cloud mode. The sidecar is unchanged.
- **R4-LOW-006:**
  - **`newsapi-headlines.js`** ignores the caller's `q` and serves the app's
    fixed query. It caches for 20 minutes, slices to the clamped `pageSize`,
    and requires `requireAppAuth`.
  - **`mediastack-news.js`** caches per normalized category set (allowlisted,
    lower-cased, de-duplicated, sorted). It always fetches the maximum and
    slices, and requires `requireAppAuth`.
  - Both now answer with `private` cache headers.
- **Existing test updated intentionally:** `tests/redis-caching.test.mjs` now
  expects the fenced context and maps the two new imports.

## Residual risks and follow-ups

- **The daily cap counts admitted requests**, cache hits included. That is a
  conservative upper bound on LLM calls, not an exact count.
- **`requireAppAuth` compares keys with `!==`,** which is not constant-time.
  This predates this PR; a timing-safe compare is a small follow-up.
- **Allowlist edge cases.** The map's `POLITICAL_OVERRIDES` path is redundant
  with `TIER1_COUNTRIES` today (both add `TW`), so no test can tell the two
  apart. Codes the map marks `-99` (for example Somaliland and Northern
  Cyprus) get 400, and the renderer falls back to its local brief.
- **The ~26 other legacy feed routes** are fixed, cached queries and stay
  ungated by design (R4-LOW-006 named only these two).
- **The R4 doc status table** lives on the handoff branch, so update it when
  that branch merges.
